## 1. Суть продукта

GiftOS — социальная PWA-платформа желаний, коллективных сборов, подарков и общения.

Основная идея не сводится к сбору денег. Пользователь должен иметь возможность показать желание, увидеть желания других людей, поддержать чужую цель, общаться вокруг сбора, знакомиться через общие интересы и возвращаться в живое сообщество.

Главная социальная механика:

```text
Люди → желания → сборы → общение → поддержка → подписки → новые люди
```

Сбор — центральный социальный объект. Он должен быть поводом для общения, поддержки, подписки, знакомства и последующего вирусного роста.

## 2. Целевой пользовательский сценарий

1. Настя регистрируется.
2. Заполняет профиль.
3. Создаёт желание, например «Хочу фотоаппарат».
4. Создаёт публичный сбор на 100 000 ₽.
5. Получает ссылку и делится ею.
6. Люди приходят на страницу сбора, смотрят профиль, поддерживают и общаются.
7. Кто-то подписывается на Настю или пишет ей.
8. Другой пользователь нажимает «Я тоже хочу», создаёт похожее желание и приглашает своих знакомых.

Основная продуктовая метрика: сколько новых пользователей приводит один активный пользователь и сколько из них создают собственное желание или сбор.

## 3. Обязательное содержание MVP

### Аккаунт и профиль

- Регистрация по email и телефону.
- Публичный профиль: имя, username, фото, город при согласии, био, интересы.
- Настройки видимости профиля, города и личных сообщений.
- Публичная страница пользователя с желаниями и сборами.

### Желания

- Создание желания без обязательного сбора.
- Название, описание, фото, примерная стоимость, категория, ссылка на товар, приватность.
- Редактирование, архивирование и клонирование через «Я тоже хочу».

### Сборы

- Создание сбора с целью, описанием, обложкой, сроком и уровнем доступа.
- Видимость: `public`, `unlisted` (по ссылке), `private`.
- Страница сбора: прогресс, цель, участники, автор, дальнейшая поддержка и чат.
- Публичный сбор должен отображаться в ленте.

### Социальная механика

- Главная лента, а не пустой личный кабинет после входа.
- Новые сборы, люди и желания — уже в ранней версии.
- Затем: популярные и быстрорастущие сборы на основе реальных действий.
- Подписка на людей и сборы, уведомления.
- Публичное обсуждение под сбором.
- Личные сообщения с блокировкой, жалобами и антиспамом.

### Безопасность и модерация

- Жалобы на пользователя, сбор и сообщение.
- Блокировка пользователей.
- Базовая административная панель.
- Особое внимание мошенническим сборам.

### Платежи

- Деньги не хранятся на обычном счёте платформы.
- Поддержка проходит через выбранного платёжного партнёра.
- Платформа получает статусы успешной операции, отмены, возврата, достижения цели и выплаты.
- Платёжный webhook должен быть проверяемым и идемпотентным.

## 4. Не входит в первый MVP

Не начинать до проверки основной социальной механики:

- прямые эфиры;
- Stars / внутренняя валюта;
- виртуальные подарки;
- полноценный маркетплейс и реальные товары;
- сложные рекомендации и ML;
- рекламная платформа;
- сложный видеоконтент.

## 5. Технические решения

| Область                 | Решение                                                      |
| ----------------------- | ------------------------------------------------------------ |
| Frontend                | Next.js 15, React 19, TypeScript, App Router                 |
| UI                      | Tailwind CSS, shadcn-совместимые компоненты                  |
| PWA                     | Web manifest уже добавлен                                    |
| Backend API / Auth / DB | Self-hosted Supabase: Auth, Postgres, RLS, Storage, Realtime |
| Изображения             | Приватный Supabase Storage + серверные signed URL            |
| Деньги                  | Будущий адаптер внешнего платёжного партнёра                 |
| Суммы                   | Только integer minor units: 2 000 ₽ = `200000`               |

### Важные правила кода

- Доступ к пользовательским данным проверяется RLS, а не скрытием кнопок.
- Браузер не может сам менять статусы поддержек.
- `SUPABASE_SERVICE_ROLE_KEY` — только в server-only коде и secrets manager.
- Нельзя показывать сырые записи `fundraiser_supports` в публичной ленте; использовать безопасный view `fundraiser_support_activity`.
- Любая новая функция оценивается по принципу: помогает ли она привлечь нового пользователя, вызвать поддержку, общение, знакомство или возвращение.

## 6. Инфраструктурное решение для РФ

### Принятое решение

Production GiftOS использует **self-hosted Supabase в российской инфраструктуре**. Supabase Cloud не применяется для production-персональных данных российских пользователей.

Причина: продукт собирает персональные данные — как минимум имя, email/телефон, город, IP/логи, фотографии, сообщения и платежные события. Первичный сбор и основной локализуемый контур должны быть размещены в РФ; юридическая модель должна быть отдельно проверена перед публичным запуском.

### Среды

```text
Local development → local Supabase + только синтетические данные
Staging           → изолированная российская инфраструктура + тестовые данные
Production        → self-hosted Supabase в РФ + реальные данные
```

### Production-план

1. Выбрать российского инфраструктурного провайдера (рассматривается Timeweb) и письменно подтвердить размещение серверов, дисков, backup и реплик в РФ.
2. Развернуть Next.js и self-hosted Supabase: Postgres, Auth, Storage, Realtime, API gateway.
3. Настроить российские SMTP/SMS-поставщики, домены, TLS, резервные копии и мониторинг.
4. Применить миграции из `supabase/migrations` через защищённый CI/CD.
5. Подключать платёжного партнёра только после выбора юридической модели.

Подробный документ: [INFRASTRUCTURE_RU.md](INFRASTRUCTURE_RU.md).

## 7. Реализовано в репозитории

### Фундамент

- Настроены lint, format, typecheck, production build.
- Supabase browser/server/admin clients.
- Миграции с доменной моделью, RLS, Storage, категориями, reports, blocks, referrals и безопасными view.

### Первый вертикальный сценарий

- Публичная страница профиля `/u/[username]`.
- Создание, редактирование, архивирование и клонирование желаний.
- Создание публичного / по ссылке / приватного сбора.
- Страница сбора с прогрессом.
- Главная страница читает реальные публичные сборы и людей после подключения базы; без окружения показывает демо-режим.
- Каталог людей и каталог публичных желаний.
- Приглашение по username в приватный сбор, журнал приглашений, принятие или отклонение доступа.
- Тестовый `PaymentProvider`, защищённая финализация поддержки и webhook-маршрут.
- Поддержка с суммой, настройками отображения и сообщением.
- Базовое обсуждение под сбором; сообщение из успешной поддержки добавляется автоматически.
- Supabase Realtime обновляет обсуждение у открывших страницу пользователей при новых сообщениях.

### Пока не реализовано

- Развёртывание production self-hosted Supabase.
- Реальный платёжный партнёр, возвраты и юридически согласованная production-модель.
- Подписки, уведомления, личные сообщения, поиск по тексту, модераторский интерфейс.
- Популярные, быстрорастущие и персональные рекомендации.

## 8. Приоритет разработки

### Приоритет 1 — социальные желания и сборы

1. Поднять локальный Supabase и применить миграции на синтетических данных.
2. Проверить реальный сценарий: регистрация → onboarding → желание → сбор → лента.
3. Проверить приглашения в приватный сбор и тестовую поддержку.
4. Добавить подписки на пользователей и сборы, затем уведомления.
5. Сделать расширенную realtime-индикацию новых сообщений и уведомлений.
6. Сделать базовые модераторские сценарии, поиск и безопасную discovery-ленту.
7. После появления активности — вычисление новых / популярных / быстрорастущих сборов.
8. Интегрировать реального платёжного партнёра только после юридической проверки и подготовить self-hosted развертывание в РФ.

### Приоритет 2 — GiftOS Activities 18+

Только после проверки основной воронки сборов и появления безопасного платёжного/модерационного контура:

1. Каталог заранее описанных adult-only услуг общения и совместных активностей.
2. Запрос → добровольное принятие → бронирование → оплата → выполнение → выплата.
3. Проверка возраста, KYC/anti-fraud, блокировки, жалобы, отмены и возвраты.
4. Никакого платного обхода личной приватности, оплаты за игнорирование или monetized interaction с несовершеннолетними.

## 9. Платные взаимодействия — гипотеза на обсуждении

Поступила идея монетизировать общение вокруг желаний и поддержек. Она **не должна** реализовываться как покупка обязательного доступа к конкретному человеку, романтического внимания или как «общение без цензуры».

Рекомендованная безопасная альтернатива для будущего этапа — отдельный marketplace понятных социальных услуг для **совершеннолетних** всех гендеров. Аналогия продукта: если FanPay продаёт цифровые товары, GiftOS Sessions продаёт **заранее описанное и добровольно забронированное время общения**, а не доступ к личности:

- заранее описанная услуга: текстовая переписка 30/60 минут или в течение согласованного периода, разговор, игровой напарник, совместная прогулка/мероприятие, наставничество, консультация;
- свободное согласие обеих сторон до начала диалога;
- прозрачная цена и время услуги, а не соревнование сумм поддержек;
- оплата через партнёра за услугу, а не «донат за право написать»;
- возрастная проверка, блокировки, жалобы, антифрод, запрет незаконного и сексуально-эксплуатирующего контента;
- обязательная модерация: подход «без цензуры» не принимается для production-платформы.

Связь со сбором может быть мягкой: поддержка повышает социальную репутацию или открывает возможность **отправить запрос** на общение, но не покупает согласие или прямой доступ к человеку.

Допустимые будущие механики:

- добровольный донат / tip без обещания ответа, общения или особых прав;
- платный **запрос на сообщение**: получатель сам принимает или отклоняет запрос, при отклонении списание не происходит или сумма возвращается через платёжного партнёра;
- оплаченная текстовая сессия с заранее указанной длительностью, правилами и взаимным согласием.

Недопустимая механика: оплата не должна автоматически обходить приватность, блокировку, возрастные ограничения или давать право писать человеку без его согласия.

### Платные виртуальные подарки

Направление Sessions отложено по запросу пользователя; рассматриваются платные виртуальные подарки. Безопасный поэтапный вариант:

1. Пользователь покупает и отправляет цифровой подарок; он отображается в профиле, под сбором или в поддержке.
2. В первом MVP подарок **не обменивается на деньги** и не создаёт свободно передаваемую валюту.
3. В будущем можно подключить реальный товар, сертификат или партнёрскую услугу с погашением у партнёра.
4. Вывод денег получателю возможен только как отдельная юридически и платёжно согласованная модель выплат за подтверждённую услугу/заказ, с KYC, anti-fraud, возвратами и налоговой проработкой. Он не должен быть свободным обменом виртуальных подарков между пользователями.

«Друг на час» — это не обмен подарка на деньги, а отдельная взрослая marketplace-услуга с добровольным бронированием, правилами безопасности и оплатой через партнёра.

### Возраст и денежные взаимодействия

MVP GiftOS Sessions должен быть **18+**. Платное общение, доход от внимания, платные запросы и любые расчёты между пользователями не проектируются для несовершеннолетних и не должны связывать взрослых с несовершеннолетними.

Если позднее появится отдельный подростковый social-режим, он может быть только бесплатным, с жёстким разделением возрастных групп, запретом adult-to-minor discovery/контакта, ограничением публичных данных, жалобами и усиленной модерацией. Любая возможность заработка несовершеннолетних требует отдельной правовой проверки, согласий и модели безопасных возрастных услуг; она не относится к отношениям, знакомствам или платным сообщениям.

Решение о включении взрослого направления в roadmap пока не принято и требует отдельной юридической, платёжной и safety-проработки.

# SEO-стратегия «Хочу также»

## Главное решение

Mobile-first тёмный creator-дизайн **не является проблемой для SEO**. Поисковым системам важны не цвета и размеры карточек, а серверный HTML, семантическая структура, уникальный текст, metadata, ссылки и скорость загрузки.

Однако публичную SEO-витрину и интерактивное приложение нужно разделить.

```text
SEO-страницы → находят новых людей из поиска
Creator-приложение → удерживает, показывает stories, подписки и действия
```

## Целевая маршрутизация

| URL                                                   | Роль                                                                        | Индексация                         |
| ----------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------- |
| `/`                                                   | Маркетинговая landing page: ценность для авторов и зрителей, категории, CTA | index                              |
| `/feed`                                               | Mobile creator feed для авторизованного/возвращающегося пользователя        | optional / noindex на раннем этапе |
| `/u/[username]`                                       | Публичная авторская страница с описанием, интересами, контентом и ссылками  | index, если публичный профиль      |
| `/wishes/[id]`                                        | Вечнозелёная публичная страница желания                                     | index, если публично               |
| `/fundraisers/[slug]`                                 | Публичный сбор с историей и прогрессом                                      | index, если `public`               |
| `/stories/[id]`                                       | Временный video content на 24 часа                                          | noindex                            |
| `/search`                                             | Внутренний поиск                                                            | noindex                            |
| `/notifications`, `/admin`, `/creator`, `/onboarding` | Персональные/служебные экраны                                               | noindex                            |

`unlisted` и `private` сборы не должны попадать в sitemap, canonical или поисковую выдачу.

## Что нужно для SEO

1. Публичные страницы должны рендерить контент на сервере. Next.js App Router и текущие Server Components уже подходят для этого.
2. Для каждого автора, желания и публичного сбора нужны:
   - уникальные `title` и `description`;
   - canonical URL;
   - Open Graph preview для Telegram/VK/мессенджеров;
   - JSON-LD (`Person`, `VideoObject`/`CreativeWork`, `Event`/`DonateAction` — только там, где соответствует содержанию).
3. Нужны `robots.txt`, динамический `sitemap.xml` и `noindex` для временных/персональных экранов.
4. В profile-first дизайне информация автора, headline, интересы, цели и публичные stories должны оставаться текстом в HTML, а не существовать только в canvas/картинке или после клиентского JavaScript.
5. Нужны быстрые медиа: preview image/poster, ограничение размера, lazy loading, последующий transcoding video stories.

## Дизайн и SEO совместимы

Публичный профиль может выглядеть как мобильная creator-страница из прототипа и при этом быть SEO-страницей:

```text
H1: Настя — автор в «Хочу также»
headline: Играю, общаюсь и публикую stories
интересы: игры, музыка, кино
публичные цели / stories / посты
```

Эти данные видит пользователь и поисковый робот. Визуальная тёмная оболочка не мешает индексации.

## Ближайшая реализация

1. Вынести mobile feed из `/` в `/feed`.
2. Сделать `/` SEO landing page, которая объясняет продукт и ссылается на публичных авторов/категории.
3. Добавить metadata/OG/robots/sitemap для существующих публичных маршрутов.
4. Добавить `noindex` для stories, поиска и авторизованных разделов.
5. После этого развивать video stories и creator-профили без потери SEO.
